# ZYRON — Autonomous Executive Intelligence System

A personal chief of staff built as a spatial web application. Twenty-three
specialist modules sit behind one orchestrator; anything that would touch the
outside world stops at a human approval gate first.

This repository is **Phase 1**: the full 3D product surface plus a working
agent runtime (intent routing, module dispatch, approval queue). It runs and
demos with zero external accounts.

---

## Run it

```bash
npm install
cp .env.example .env.local     # optional
npm run dev                    # http://localhost:3000
```

Fonts are self-hosted from npm (`@fontsource-variable/*` plus `geist`), not
fetched from Google Fonts at build time. The whole app installs and builds with
no access to any host other than the npm registry.

Two surfaces:

| Route      | What it is                                                       |
| ---------- | ---------------------------------------------------------------- |
| `/`        | The system overview — every section is a real 3D scene            |
| `/console` | The working console: send a command, watch it route, approve work |

**Without an API key** the console runs in deterministic simulation mode. The
router, the module dispatch and the approval queue are all real; only the prose
is generated by rules instead of a model. This is intentional — a live demo
should never depend on a network.

**With a key**, add to `.env.local`:

```
ANTHROPIC_API_KEY=sk-ant-...
```

The approval card is still generated by the router, never by the model. The
safety gate must not depend on the model choosing to cooperate.

## How a command flows

```
composer ──► /api/agent ──► routeIntent()  ──► module selection + risk class
                                │
                                ├── risk: autonomous ──► answer, done
                                └── risk: approval / sealed
                                          │
                                          ▼
                                  approval queue ──► you tap ──► dispatch
```

`src/lib/agent/router.ts` is deliberately written as inspectable keyword
signatures rather than a black box. In a viva you can point at the exact line
that explains why a command went where it went.

Risk classes:

- **autonomous** — reading, sorting, drafting, analysing. Runs alone.
- **approval** — sending, spending, publishing, booking, cancelling. Asks.
- **sealed** — continuity release, crisis mode, legacy vault, data deletion.
  Asks, and is marked for a second confirmation.

## Palette and materials

Black, gold, chocolate, cream. Gold is the user's authority, chocolate is the
machine, cream is everything the user reads. Tokens live in
`tailwind.config.ts`:

| Token     | Hex       | Used for                          |
| --------- | --------- | --------------------------------- |
| `ink`     | `#080605` | Page ground                       |
| `obsidian`| `#12100D` | Panels and rails                  |
| `gold`    | `#D9A441` | Authority, approvals, core modules|
| `cocoa`   | `#7A4F2E` | The machine layer, extended tier  |
| `cream`   | `#F7F2E8` | Text                              |
| `ash`     | `#B5A794` | Secondary text                    |

The 3D objects are polished metal (`meshPhysicalMaterial`, `metalness: 1`,
low roughness, `clearcoat`) lit by a Lightformer environment. That combination
is what makes a gold ring read as a machined object rather than a coloured
circle: the specular highlight travels across the surface as the object turns.
`ContactShadows` grounds the floating slabs.

**The environment map is built in-scene, never downloaded.** `<Environment
preset="city" />` fetches an HDR from a CDN at runtime; if that request stalls,
the Suspense boundary never settles and the whole canvas renders nothing — the
page looks like it has no 3D at all. `StageLights` builds the map from
`<Lightformer>` panels instead, so it is instant and works offline.

## 3D performance and failure rules

Seven WebGL scenes on one page is a real risk, so:

- Every canvas goes through `SceneCanvas`, which mounts only when the section
  is within 300px of the viewport.
- `dpr={[1, 1.75]}` plus `AdaptiveDpr` — retina screens do not render at 3x.
- `prefers-reduced-motion` skips the canvases entirely.
- All `useFrame` work uses frame-rate-independent damping, not fixed steps.

**When WebGL is unavailable**, the page must not break. Two guards:

1. `detectWebGL()` probes for a context once and caches the result. If there
   is none, no canvas is ever mounted.
2. `CanvasBoundary` catches the throw from three.js, which happens inside a
   layout effect and would otherwise be a fatal render error for the whole
   page. One dead canvas costs a background, not the site.

Either way the section renders `SceneFallback` — a CSS-only light source and
hairline sphere in the same palette. The layout, the copy and the console all
keep working.

Common causes on a demo machine: hardware acceleration switched off in the
browser, a blocklisted GPU driver, or too many live contexts across open tabs.
`chrome://gpu` names the reason.

## Storage — phase 2

State survives a reload: approvals, commitments, the transcript and an
append-only audit trail.

**Without `MONGODB_URI`** the app uses an in-memory store. Everything behaves
identically; state is lost when the server restarts. Fine for a quick demo.

**With MongoDB Atlas** (the free M0 tier is plenty):

1. Create a free cluster at https://cloud.mongodb.com
2. Database Access -> add a user, copy the password
3. Network Access -> Add IP -> Allow access from anywhere (0.0.0.0/0). Fine
   for a project; tighten it for anything real.
4. Connect -> Drivers -> copy the connection string
5. Put it in `.env.local`, replacing `<password>` with the real one:

```
MONGODB_URI=mongodb+srv://user:password@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
MONGODB_DB=zyron
```

Restart the dev server. The rail footer changes from "In-memory session" to
"MongoDB connected". Indexes are created automatically on first write.

### Collections

| Collection    | Holds                                                       |
| ------------- | ----------------------------------------------------------- |
| `approvals`   | Every staged action and how you answered it                  |
| `commitments` | Promises extracted from your own words, with owner and date  |
| `messages`    | The console transcript                                       |
| `events`      | Append-only audit trail — the record the PRV module promises |

Swapping database is one new class against the `ZyronStore` interface in
`src/lib/db/store.ts`. Nothing else in the app changes.

### API surface

| Route                   | Method   | Purpose                         |
| ----------------------- | -------- | ------------------------------- |
| `/api/agent`            | `POST`   | Route a command, persist result |
| `/api/state`            | `GET`    | Hydrate the console in one call |
| `/api/state`            | `DELETE` | Delete everything for the user  |
| `/api/approvals`        | `GET`    | The queue                       |
| `/api/approvals/[id]`   | `PATCH`  | Approve, edit or cancel         |
| `/api/commitments`      | `GET`    | The tracker                     |
| `/api/commitments/[id]` | `PATCH`  | Nudge or close                  |

Writes are wrapped so a storage failure degrades the feature instead of taking
the conversation down, and the console rolls back its optimistic update if a
decision could not be saved — it will not tell you something was dispatched
when it was not.

## Accessibility and quality floor

- Keyboard focus is visible on every interactive element
- Reduced motion honoured across CSS, Framer Motion and WebGL
- Every canvas is `aria-hidden` — no meaning lives only in the 3D layer
- Responsive from 360px up; the console collapses its rails on small screens
